Đọc phần này trước

Sentinel hiện đang ở đâu?

Luồng policy-driven end-to-end đã hoạt động trong console: hiểu request, lưu policy, đọc Binance Demo, tính toán, kiểm tra risk và giải thích kết quả.

ĐÃ HOẠT ĐỘNG

Policy-driven runtime

main.py chạy controlled tool loop. LLM tự chọn capability tiếp theo; Python giữ quyền tính toán và RiskEngine.

ĐÃ HOẠT ĐỘNG

Policy core

Năm controlled tools, session RAM, allocation, violation, rebalance và RiskEngine đã nằm trong console loop.

TƯƠNG LAI

Ứng dụng hoàn chỉnh

FastAPI, UI thật, activity stream, Approve/Reject, execution và verification chưa được triển khai.

Bốn giới hạn cần nhớ.

UI hiện tại là bản tĩnh; tiến trình phân tích trên web đang được mô phỏng.

Quá trình xây dựng

Tại sao dự án có hình dạng này?

Mỗi thay đổi giải quyết một câu hỏi kiến trúc cụ thể. Mục tiêu không phải nhiều lớp, mà là giữ LLM linh hoạt trong khi logic tài chính vẫn có thể kiểm thử.

  1. 01 · HỌC AGENT

    Mock tools

    Bắt đầu với portfolio và market giả để nhìn rõ việc LLM quyết định khi nào cần gọi hàm.

  2. 02 · MODEL ROUTING

    LiteLLM

    Thêm một route chung để đổi Gemini/OpenAI bằng cấu hình mà không viết lại Agent.

  3. 03 · SAFETY CORE

    Policy + Risk

    Tách hiểu ngôn ngữ khỏi phép tính, threshold và quyết định an toàn bằng Python deterministic.

  4. 04 · DISCOVERY

    MCP không phù hợp

    Custom Agentic MCP OAuth bị Binance từ chối với lỗi Agent chưa được hỗ trợ, nên runtime MCP được gỡ bỏ.

  5. 05 · TRACK A

    Skills Hub CLI

    Chuyển sang binance-cli chính thức, chỉ expose capability đọc/evaluate ổn định và dùng Binance Demo.

Quyết định quan trọng: Sentinel không cho LLM thấy toàn bộ Binance CLI. LLM chỉ thấy năm capability theo ngôn ngữ nghiệp vụ; gateway mới biết command kỹ thuật bên dưới.

Architecture rule

Ai chịu trách nhiệm việc gì?

AI giỏi hiểu ngữ nghĩa nhưng không phải nơi đáng tin cho phép tính và quyền tài chính. Sentinel đặt mỗi loại quyết định vào đúng tầng.

TầngĐược làmKhông được làmCode chính
LLM Hiểu ý định, tự chọn tool tiếp theo và đưa nhận định định tính. Bịa dữ liệu, quyết định phép tính authoritative, chạy lệnh Binance. app/agent/
AI tools Đọc dữ liệu, stage policy và gọi deterministic evaluation trong runtime chính. Chứa business rule hoặc nhận command tùy ý. app/agent/controlled_tools.py
Gateway Chọn command cố định, validate payload ngoài, map vào domain. Expose shell, URL hoặc generic request cho LLM. app/binance/
Python services Tính total, weight, violation, proposal và risk theo rule. Hiểu câu tự nhiên hoặc tự gọi API ngoài. app/services/
RiskEngine BLOCKED ưu tiên hơn APPROVAL; trả reason code rõ ràng. Nhận kết luận an toàn từ LLM mà không tự kiểm tra. risk_service.py
Người dùng Giữ key local, định nghĩa policy, phê duyệt khi tương lai có execution. Gửi secret qua chat hoặc frontend. .env local

System rail · runtime thật

Một câu hỏi chạy qua hệ thống

Ví dụ: “Analyze my BTC exposure and tell me whether it currently looks risky.” Đây là luồng có thể chạy ngay sau khi cấu hình LLM key và Binance Demo key.

  1. 01

    User nhập câu hỏi

    main.py đọc input và chuyển câu chat cùng session ID vào SentinelApplication.

    main.py
  2. 02

    Sentinel Agent hiểu ý định và chọn tool

    LLM qua LiteLLM nhận current policy cùng năm tool schemas, rồi tự chọn capability an toàn cần gọi.

    app/agent/tool_loop.py
  3. 03

    Tool result quay lại LLM

    SDK chạy tool model đã chọn, trả Pydantic result vào conversation, rồi gọi LLM lại để nó quyết định bước kế tiếp.

    app/agent/controlled_tools.py · app/agent/run_context.py
  4. 04

    Agent quan sát portfolio và market

    get_portfolio và get_market_data chỉ trả dữ liệu đã qua gateway; LLM không được tự tạo số liệu.

    app/agent/controlled_tools.py
  5. 05

    Gateway và runner đọc Binance Demo

    Gateway chọn command read-only đã hard-code; runner dùng argument array, không mở shell, đặt timeout và cô lập credentials.

    app/binance/gateway.py · app/binance/runner.py
  6. 06

    Python tính và kiểm tra an toàn

    Decimal services tính allocation, violations, proposal; RiskEngine quyết định BLOCKED, REQUIRES_APPROVAL hoặc SAFE_TO_PROPOSE.

    policy_service.py · rebalance_service.py · risk_service.py
  7. 07

    Python render facts, LLM thêm interpretation

    PortfolioAnalysis đã validate được Python render thành facts và formal RiskStatus. Cùng Agent viết interpretation có nhãn; output chứa formal status hoặc claim execution trái phép sẽ bị từ chối.

    app/application.py · app/agent/output_safety.py

Tại sao đây là Agent chứ không chỉ là chatbot?

Chatbot thông thường chỉ tạo câu trả lời. Sentinel để LLM nằm trong vòng lặp: chọn tool, quan sát kết quả, chọn bước tiếp theo và cuối cùng đưa nhận định. Python vẫn độc quyền tính toán và quyết định an toàn. Đây là agentic workflow có ranh giới, không phải LLM tự do điều khiển Binance.

Domain core

Policy qua chat hoạt động thế nào?

Console đã hỗ trợ cập nhật, xem và phân tích policy bằng câu chat tự nhiên trong cùng một session.

ĐÃ HOẠT ĐỘNG

Phần hiểu ngôn ngữ

  1. User chat“Giữ ít nhất 30% USDT và phân tích ngay.”
  2. Sentinel AgentHiểu intent và gọi update_policy trước các tool phân tích khi user yêu cầu cả hai.
  3. Pydantic validationChặn field lạ, threshold sai, duplicate change và giá trị không hợp lệ.
  4. Staged commitPolicy chỉ vào session sau khi toàn bộ Agent run thành công; user vẫn nhận tiếng Việt tự nhiên.
ĐÃ HOẠT ĐỘNG

Phần quyết định deterministic

  1. Portfolio serviceTính total và weight bằng Decimal.
  2. Policy serviceSo sánh allocation với giới hạn đã validate.
  3. Rebalance serviceTạo draft action từ phần allocation vượt ngưỡng.
  4. Risk serviceTrả BLOCKED, REQUIRES_APPROVAL hoặc SAFE_TO_PROPOSE.
USER INTENT
    ↓
LLM chooses controlled tools
    ↓
SDK returns each validated tool result to LLM
    ↓
Python observes portfolio + calculates violations
    ↓
Planner creates proposal
    ↓
RiskEngine validates deterministically
    ↓
LLM explains in natural language
Điểm an toàn: evaluate_portfolio_risk là cửa duy nhất tạo analysis và luôn gọi policy checks, planner rồi RiskEngine. SentinelApplication render event đúng thứ tự và chỉ commit staged policy sau khi Agent thành công.

Source atlas

Entry point & cấu hình

main.py

Composition root: load config, tạo runner → gateway → SentinelToolLoop → SentinelApplication.

Phụ thuộc: config và các implementation ở rìa. Được gọi bởi: người dùng qua python main.py.

app/application.py

Use-case boundary: chạy Agent loop, commit staged policy sau thành công, render authoritative facts rồi nối AI interpretation.

Không phụ thuộc: Binance CLI cụ thể. Output: SentinelResponse gồm text, policy và optional analysis.

app/config.py

Đọc `.env`, validate provider/model/key, khóa Binance ở Demo và tạo LiteLLM route.

Input: environment variables. Output: immutable Settings. Dùng bởi: main, Agent, CLI runner.

app/gateways.py

Protocol do application sở hữu, định nghĩa get_portfolio() và get_market_data().

Phụ thuộc: domain models. Được implement bởi: BinanceCliGateway. Dùng bởi: controlled tool handlers.

app/sessions.py

Lưu PortfolioPolicy theo session ID trong RAM và apply patch đã validate.

Phụ thuộc: policy model/service. Dùng bởi: SentinelApplication sau Agent run thành công. Mất dữ liệu khi process dừng.

app/__init__.py

Đánh dấu app là Python package. File có thể rỗng vì vai trò chính là ranh giới package/import.

Tương tự: các __init__.py trong agent, binance, models, services, tools và tests/unit.

.env.example

Template tên biến cấu hình, chỉ chứa placeholder. `.env` thật bị ignore và không bao giờ đi vào frontend.

Dùng bởi: developer khi setup. Không được import: đây không phải source code.

requirements.txt

Liệt kê các package Python: Agents SDK với LiteLLM extra, dotenv, Pydantic và pytest; hiện chỉ LiteLLM được pin phiên bản cụ thể.

Dùng bởi: pip khi dựng virtual environment. Không chứa: MCP, web framework hay Binance SDK riêng.

.gitignore

Ngăn `.env`, virtual environment, cache và artifact local đi vào Git.

Vai trò an toàn: secret local không xuất hiện trong commit chỉ vì developer chạy ứng dụng.

Agent & AI tools

app/agent/tool_loop.py

Runtime chính: tạo text-output Agent với đúng năm controlled tools, tạo context mới và để SDK tiếp tục loop sau mỗi tool result.

Input: message + current policy. Output: final text, ordered events, staged patches và validated analyses.

app/agent/controlled_tools.py

Định nghĩa năm tool đọc portfolio/market, update/view policy và deterministic risk evaluation. Không có execution tool.

Ủy quyền: gateway cho I/O, services cho tính toán. Không được: nhận CLI command tùy ý.

app/agent/run_context.py

Giữ working policy, trusted observations, event order và analyses trong đúng một Agent run; không chứa credentials.

Commit: staged patches chỉ được application ghi vào session sau khi run thành công.

app/agent/sentinel.py

Legacy: Agent hai-tool để minh họa cơ bản; file vẫn có test nhưng không còn là runtime policy chính.

Input: Settings + PortfolioMarketGateway. Output: Agents SDK Agent. Dùng để học: autonomous tool calling.

app/agent/prompts.py

Giữ instructions của controlled tool loop và các Agent legacy tách khỏi construction code.

Quy tắc: không bịa dữ liệu, không trade; analysis phải qua deterministic evaluation tool.

app/agent/request_interpreter.py

Legacy: tool-free LLM Agent với output_type=ParsedRequest. Được giữ để học/so sánh, không được main.py khởi tạo.

Lý do thay: runtime mới dùng tool schemas nhỏ thay cho một union structured-output phức tạp.

app/agent/analysis_reporter.py

Legacy: Reporter tách riêng. Runtime mới để chính Agent trong tool loop viết interpretation sau khi nhận validated analysis.

Không được: gọi Binance, tính lại số liệu, sửa policy, plan hoặc RiskDecision.

app/tools/portfolio.py

Legacy educational wrapper; runtime chính dùng handlers trong controlled_tools.py.

Input: không có argument. Output: Portfolio. Ủy quyền cho: gateway; không tự đọc Binance.

app/tools/market.py

Legacy educational wrapper; runtime chính dùng handlers trong controlled_tools.py.

Input: pair như BTCUSDT. Output: MarketData hoặc MarketDataError. Không được: tự tạo giá.

app/agent/__init__.py và app/tools/__init__.py

Đánh dấu package và cho phép API package rõ ràng về sau. Hiện để rỗng để tránh side effect khi import.

Không phải: nơi bắt buộc đặt business logic hoặc tự động khởi tạo Agent.

Binance adapter

app/binance/runner.py

Chạy executable bằng asyncio.create_subprocess_exec, argument array, timeout và JSON parsing.

Input: danh sách argument cố định từ gateway. Output: parsed JSON. Bảo mật: sanitize mọi lỗi.

app/binance/gateway.py

Adapter chính: chọn bốn command read-only, validate symbol, map payload và tính volatility/slippage.

Phụ thuộc: runner, transport schemas, portfolio service. Implement: PortfolioMarketGateway.

app/binance/schemas.py

Pydantic transport models phản ánh JSON ngoài từ account, ticker, 24h stats và depth.

Ranh giới: payload Binance phải qua schema này trước khi thành domain model.

app/binance/__init__.py

Đánh dấu external adapter package; giữ rỗng để import package không tự gọi subprocess hoặc mạng.

Nguyên tắc: import không có side effect.

Domain models

app/models/portfolio.py

PortfolioAsset và Portfolio: amount, USD value, weight, total và source.

Tạo bởi: gateway/portfolio service. Dùng bởi: tools, policy, planner.

app/models/market.py

MarketData, volatility enum và error result cho failure không crash Agent.

Tạo bởi: Binance gateway. Dùng bởi: market tool, planner, RiskEngine.

app/models/policy.py

Validated policy, partial patch và policy violations với Decimal threshold từ 0 đến 1.

Dùng bởi: controlled update tool, sessions, policy service và risk service.

app/models/chat.py

Legacy discriminated union của Request Interpreter cũ; không còn ở console runtime.

Giữ lại: test và tài liệu so sánh cho tới khi legacy flow được dọn.

app/models/trade.py

TradeAction và RebalancePlan là proposal data; model tồn tại không đồng nghĩa có execution.

Tạo bởi: rebalance service. Đọc bởi: risk service.

app/models/risk.py

RiskStatus, reason codes và RiskDecision machine-readable.

Tạo bởi: risk service. Mục đích: không dùng câu văn LLM làm quyền thực thi.

app/models/source.py

DataSource gắn provenance cho kết quả. Runtime hiện luôn trả BINANCE_DEMO.

Dùng bởi: Portfolio và MarketData để tránh gọi số dư mô phỏng là tiền thật.

app/models/analysis.py

Aggregate đã validate và khóa ở top-level, gồm policy, portfolio, violations, market data, plan và risk decision.

Tạo bởi: deterministic observation evaluator. Đọc bởi: Agent và application formatter.

app/models/__init__.py

Package marker cho domain model; không re-export hàng loạt để dependency vẫn dễ truy vết.

Được import theo file cụ thể: ví dụ app.models.policy.

Deterministic services

app/services/portfolio_service.py

Tính tổng USD và từng weight bằng Decimal; validate portfolio không rỗng và total hợp lệ.

Input: assets đã định giá. Output: Portfolio. Dùng bởi: Binance gateway.

app/services/policy_service.py

Apply patch theo field được gửi và tìm concentration/stablecoin violations.

Phụ thuộc: policy + portfolio models. Không phụ thuộc: LLM/Binance.

app/services/policy_conversation_service.py

Legacy service điều phối typed actions của Request Interpreter cũ.

Không còn dùng bởi: main hoặc SentinelApplication runtime hiện tại.

app/services/policy_response_service.py

Chuyển policy update/current policy thành câu tiếng Việt dễ đọc.

Input: validated policy/patch. Output: natural-language text, không trả JSON thô cho user.

app/services/analysis_response_service.py

Render portfolio, market, violations, proposal, formal RiskStatus và NOT_EXECUTED bằng Python.

Lý do: facts hiển thị không phụ thuộc vào lời văn tự do của LLM Reporter.

app/services/rebalance_service.py

Tính lượng exposure vượt max, draft SELL value và amount từ market price.

Output chỉ là proposal. File này không có API hoặc lệnh đặt order.

app/services/risk_service.py

Áp priority: high volatility BLOCKED trước, trade threshold REQUIRES_APPROVAL sau, còn lại SAFE_TO_PROPOSE.

Input: policy + plan + market. Output: RiskDecision deterministic.

app/services/portfolio_analysis_service.py

Chứa cả use case cũ và các hàm pure mà controlled evaluation tool dùng để tìm market cần thiết, tạo plan và chạy RiskEngine.

Fail closed: thiếu observation bắt buộc thì không tạo recommendation.

app/services/__init__.py

Package marker cho pure business services, không chạy khởi tạo hoặc I/O khi import.

Giữ layer sạch: services không import Agents SDK, LiteLLM hay binance-cli.

Mapping portfolio

free + locked = amount
amount × ASSETUSDT price = usd_value
sum(usd_value) = total_usd_value
usd_value ÷ total = weight

USDT được định giá bằng 1 trong adapter Demo. Nếu một asset không có cặp ASSETUSDT, Sentinel dừng thay vì tự đoán conversion path.

Market interpretation deterministic

|change_24h| < 2%       → LOW
2% ≤ |change_24h| < 4%  → MEDIUM
|change_24h| ≥ 4%       → HIGH

Slippage được ước lượng bằng cách walk bid depth cho reference sale 1.000 USDT. Nó là dữ liệu phân tích, không phải order.

Threat boundaries

Những xem xét an toàn

Rủi ro chính không chỉ là lộ key. Một prompt độc hại cũng không được phép biến thành shell command hoặc hành động tài chính.

Không shell

Dùng create_subprocess_exec(executable, *arguments), không dùng shell=True. Symbol còn phải match regex trước khi thành argument.

Credential tối thiểu

Public market commands không nhận key. Chỉ account command authenticated nhận Binance credentials qua child environment; LLM keys không đi theo.

Không expose CLI

LLM không được truyền command hoặc URL. Không có generic request, order, cancel, transfer hay withdraw trong application path.

Fail closed

Timeout, exit code khác 0, JSON sai, schema sai, thiếu price/depth đều trả lỗi an toàn. Không fallback về mock khiến user tưởng dữ liệu cũ là thật.

Demo only

Config từ chối prod; gateway kiểm tra lại Demo. Hai tầng guard ngăn việc holdings thật bị LLM gắn nhãn mô phỏng.

Structured provenance

data_source=BINANCE_DEMO nằm trong Portfolio/MarketData, không chỉ nằm trong câu prompt dễ bị quên.
